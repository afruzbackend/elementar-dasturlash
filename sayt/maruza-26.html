Xatolarni tuzatish va dastur ishlashini tekshirish

Slaydlarda Chop etish

Maqsad: O‘quvchilarga topilgan xatolarni yangi xato kiritmasdan tuzatish, sozlash (debugging) vositalaridan foydalanish va tuzatilgan dastur ishlashini qayta sinash bo‘yicha amaliy ko‘nikmalar berish.

Reja:
  1. Xatoni tuzatish (debugging) jarayonining bosqichlari
  2. Sozlash vositalari: nazorat print(), thonny va idle debuggerlari, try-except
  3. Amaliy mashq: dasturni tuzatish, qayta sinash va yaxshilash

1. Xatoni tuzatish (debugging) jarayonining bosqichlari

Debugging nima?

Debugging (sozlash) — dasturdagi xatoni topish, sababini aniqlash va uni bartaraf etish jarayoni. Xatoni topishning o‘zi yarim ish: tuzatish paytida shoshilish ko‘pincha yangi xatoga olib keladi. Masalan, chegara xatosini tuzataman deb range() ni o‘zgartirgan o‘quvchi boshqa joyda sanoqni buzib qo‘yishi mumkin. Shuning uchun tuzatish ham aniq tartib asosida bajariladi.

Tuzatish bosqichlari

  • Xatoni takrorlash: qaysi kiritish qiymatida xato chiqishini aniqlash va yozib qo‘yish.
  • Joyini aniqlash: kuzatish jadvali, nazorat print() yoki debugger yordamida xato satrni topish.
  • Sababini tushunish: nima uchun aynan shu satr noto‘g‘ri ishlayotganini izohlash.
  • Bitta o‘zgartirish kiritish: bir vaqtda faqat bitta joyni tuzatish.
  • Qayta sinash: avval xato bergan qiymat bilan, so‘ng ilgari to‘g‘ri ishlagan barcha qiymatlar bilan tekshirish.

Oxirgi qadam regressiya testi deb ataladi: tuzatish dasturning ilgari to‘g‘ri ishlagan qismini buzmaganiga ishonch hosil qilinadi.

2. Sozlash vositalari: nazorat print(), thonny va idle debuggerlari, try-except

Nazorat print() va assert

Eng oddiy usul — shubhali joyga vaqtincha print() qo‘yib, o‘zgaruvchilar qiymatini ko‘rish. Xato tuzatilgach, bu satrlar olib tashlanadi. assert operatori esa shart yolg‘on bo‘lsa, dasturni AssertionError bilan to‘xtatadi: masalan, assert 0 <= ball <= 100, "Ball 0 dan 100 gacha bo‘lishi kerak" satri noto‘g‘ri ballni darhol fosh qiladi.

Thonny va IDLE debuggerlari

  • Thonny: Run → Debug current script (Ctrl + F5) — dastur qadamba-qadam rejimda ishga tushadi.
  • Step over (F6): joriy satrni to‘liq bajarib, keyingisiga o‘tadi.
  • Step into (F7): ifoda ichiga kirib, uni qismlab hisoblashni ko‘rsatadi.
  • View → Variables: o‘zgaruvchilarning joriy qiymatlari oynasi.
  • IDLE: Shell oynasida Debug → Debugger yoqiladi, so‘ng dastur F5 bilan ishga tushiriladi; Step, Over, Go tugmalari bilan boshqariladi.

Noto‘g‘ri kiritishni ushlash: try-except

Foydalanuvchi son o‘rniga harf kiritsa, int() ValueError beradi va dastur to‘xtaydi. try-except bloki bu holatni ushlab, qayta so‘rash imkonini beradi.

3. Amaliy mashq: dasturni tuzatish, qayta sinash va yaxshilash

Amaliy mashq: raqamlar yig‘indisi

Kerakli jihozlar: Thonny o‘rnatilgan kompyuter. Xavfsizlik: quyidagi xatoli dastur cheksiz siklga tushadi — uni Thonny dagi «Stop» tugmasi yoki IDLE da Ctrl + C bilan to‘xtating. Dastur sonning raqamlari yig‘indisini topishi kerak edi.

Xatoli kodTo‘g‘rilangan kod
n = int(input("Son: "))n = abs(int(input("Son: ")))
s = 0s = 0
while n > 0:while n > 0:
s += n // 10s += n % 10
n = n % 10n = n // 10
print("Yig‘indi:", s)print("Yig‘indi:", s)
  • Xatoli kodni Thonny da Ctrl + F5 bilan ishga tushiring, 1234 kiriting va F6 orqali n hamda s ning o‘zgarishini kuzating: n = 4 da to‘xtab qoladi, sikl tugamaydi.
  • Sababni aniqlang: oxirgi raqam n % 10, raqamni olib tashlash esa n // 10 bilan bajariladi — ikki amal adashtirilgan.
  • Birinchi tuzatishni kiriting va qayta sinang: 1234 → 10.
  • Chegaraviy qiymatlarni tekshiring: 0 → 0, 7 → 7, -507 → 0 (xato!).
  • abs() qo‘shib manfiy sonlar xatosini tuzating: -507 → 12; so‘ng 1234, 0, 7 ni yana sinang (regressiya testi).

AMALIY TOPSHIRIQ

Uchta xatoli dasturni tuzating: raqamlar yig‘indisi, 1 dan n gacha sonlar o‘rtachasi va menyuli kalkulyator (harf kiritilganda to‘xtab qoladi). Har bir dastur uchun xatoni debuggerda topib, bittalab tuzating, try-except yordamida noto‘g‘ri kiritishni ushlang va kamida 4 ta test qiymati (oddiy, nol, manfiy, harf) bilan regressiya testini o‘tkazing. Natijalarni «Test qiymati — kutilgan — olingan» jadvalida ko‘rsating. Baholash: xatolar to‘liq tuzatilgani, yangi xato kiritilmagani, debuggerdan foydalanish va test jadvalining to‘liqligi asosida.
